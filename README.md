# テトクラ — Tetcla

ブラウザーで遊べるオンライン対戦ブロックパズルです。現在は **ゲスト／メールログイン・ユーザー別40LINE自己ベスト・エンドレス・40LINE・招待ルーム／ランダムマッチングでのオンライン対戦・ゲームパッド／タッチ入力** に対応しています。

公開版: **[https://tetcla.shianstudio.com/](https://tetcla.shianstudio.com/)**

### 広告

PCではi-mobileの160×600バナー（pid: `85394`、mid: `596128`、asid: `1943446`）をゲームの左右に1枠ずつ表示します。同じ広告タグを左右で使うため、それぞれ独立したiframe内に配置しています。

スマホでは画面下部に320×50のバナー枠（320×50 / 640×100素材用、pid: `85394`、mid: `596133`、asid: `1943447`）を1枠表示し、縦長広告は読み込みません。PC／スマホの切り替え時には不要な広告を取り除きます。表示領域に入った枠だけを読み込み、ゲーム開始やモード変更では再読み込みしません。

広告が届かない間は、サイト側の仮表示「広告配信待ち」を出します。配信用iframeまたは画像リンクが挿入されると仮表示を消します。広告の内容と配信開始時期はi-mobile側の設定・審査・配信状況に依存します。

### スマホ操作

幅760px以下、またはタッチを主な入力とする幅1100px以下の端末では、自動でスマホ用レイアウトに切り替わります。縦向きでは盤面の下、横向きでは盤面の左右の下部に操作ボタンが表示されます。

- 左側の十字キー：左右で移動、下でソフトドロップ、上でハードドロップ。
- 十字キーの左上：HOLD。
- 右側：左回転と右回転。

長押し移動と複数の指での同時操作に対応し、指のキャンセル・画面回転・タブ切り替えでは押下状態を解除します。タッチ操作はエンドレス・40LINE・オンライン対戦で利用でき、リプレイにも記録されます。PCのキーボード／ゲームパッドも引き続き利用できます。

## 起動

Node.js 24 LTS推奨（最低22.12）。

```bash
npm ci
npm run dev
```

[http://localhost:5173](http://localhost:5173) を開いて「プレイする」を押します。ゲームパッドは **localhost または HTTPS** で使ってください。別端末からHTTPのLANアドレスで開くと、ブラウザーの制限によりゲームパッドを取得できない場合があります。

WSLで作業する場合は、Node.jsとnpmもWSL側にインストールしてください。Windows側のnpmが呼ばれると、`CMD.EXE`のUNCパスエラーや`vite`が見つからないエラーで起動できません。WSLのターミナルで次を確認できます。

```bash
command -v node npm  # 両方ともLinux側のパスであること（/mnt/c/... はWindows側）
node -p 'process.platform'  # linux
```

Node.jsをインストールした直後も以前のnpmが呼ばれる場合は、`hash -r`を実行するか、WSLのターミナルを開き直してください。Windows側のnpmを使っていた場合は、WSL側で`npm ci`を実行して依存関係を入れ直してから`npm run dev`を実行します。`Port 5173 is already in use`なら、すでに起動しているゲームを上記URLで開くか、そのサーバーを停止してから再実行してください。

```bash
npm run build     # 型チェック＋配信用dist生成
npm run preview   # ビルドしたゲームを確認
```

## アカウント・40LINE自己ベスト（Cloudflare）

Cloudflare Pages → Pages Functions → API Worker → D1 の構成を追加しました。アクセス時はゲストになり、「ログイン」から新規登録・メール／パスワードでのログインができます。40LINEをクリアすると検証済みタイムを保存し、40LINE画面に自己ベストを表示します。ゲストの記録は新規登録時に引き継ぎます。

APIもローカルで試す場合は、`npm run db:local`、`npm run dev:api`を実行し、別ターミナルで`npm run dev`を起動します。Cloudflareへの公開・DB作成・GitHub Secrets設定・API仕様は[Cloudflareアカウント機能](docs/cloudflare-accounts.md)を参照してください。

GitHub Pages単体の配信はゲームのみです。既存のPagesワークフローでは`VITE_ACCOUNTS_ENABLED=false`を設定し、APIのない公開先にログイン画面を表示しません。Cloudflare用ビルドではアカウント機能が既定で有効です。

## オンライン対戦（P2P・ゲームサーバー不要）

**GitHub Pagesなどの静的ホスティングだけでゲームを配信できます。** 対戦はWebRTC DataChannelでブラウザー同士を接続し、ルーム作成者（ホスト）のブラウザーが共通エンジンを60Hzで実行します。Node.jsのゲームサーバーを運用する必要はありません。

1. 「ルーム対戦」→「ルームを作成」を選び、ハンデを設定して「作成する」を押します。ハンデは「なし」、または1P（作成者）／2P（参加者）のどちらかを選び、各消去で送るライン数を−1〜−3ラインに設定できます。相殺後の送信ライン数から差し引き、最低0ラインです。双方に設定を表示し、次ラウンド・再戦でも維持します。
2. 6文字の招待コード、または「招待リンクをコピー」で取得したURLを相手に共有します。
3. 相手が「ルームに参加」を押して招待コードを入力し、「参加する」を押します。招待リンクから開くとコード入力画面が開きます。双方が「準備完了」を押すと開始します。
4. 2本先取です。結果を3秒表示した後、次ラウンド・再戦の開始カウントダウンへ自動で進みます。終了するときは「モード選択へ」を押してください。切断中は次へ進まず、復帰を待ちます。

各端末では **操作設定の「自分の操作」** のキーボード／パッドを使います。参加者は右の2P盤面を操作します。**ホストは対戦中、このタブを前面で開いたままにしてください。** ホストのPCのスリープやブラウザーの停止は試合の進行に影響します。ホストがページを更新・終了すると試合は復元できません。参加者は接続が切れた後、ホストが残っていれば10秒以内に自動再接続／同じタブの再読み込みで復帰できます。

### ランダムマッチング

「ランダム対戦」を押すとすぐに相手が現れるまで待機し、組み合わせが決まると自動で対戦を始めます。コード入力・準備完了ボタンは不要です。「キャンセル」で待機を取り消せます。ランダム対戦は常にハンデなしです。

待機中のブラウザーが共有の仲介IDを取得し、次の参加者がそこへP2P接続して招待コードを交換します。対戦開始後は待機用IDを解放して次の組を受け付けます。ゲームデータは従来どおりP2Pです。PeerJS Cloudの一覧取得APIや追加の自前サーバー・データベースは使いません。

この方式は小規模な対戦向けです。地域・レート・待ち順を保証するマッチングや不正対策はありません。仲介サービスや相手とのP2P接続が使えない場合は成立しません。必要な回線ではTURNを設定してください。仲介IDの指定・衝突・解放は[PeerJSのAPI](https://peerjs.com/client/api/peer)を使っています。

### 操作の遅延と描画負荷

参加者の移動・回転・HOLD・ドロップは、通信の返答を待たずに手元で先行表示します。ホストから届く確定状態と処理済み入力番号（ACK）で補正し、未処理の操作だけを再適用します。判定はホストに集約し、未公開のNEXTやおじゃまの穴は推測しません。その場合は確定状態を待つため、回線状況によって補正や待ちが発生します。

ホストは60Hzで表示を更新し、参加者への状態配信は通常30Hzです。盤面を短い文字列へ変換して通信量を減らし、変化のない盤面・HOLD・NEXTは再描画しません。エンドレス・40LINEは手動で再開できます。

消去時の文字はT-SPIN系と4ライン同時消去の「4LINES」を盤面上部に半透明で表示します。通常の1〜3ライン消去・全消し・REN・B2Bの文字は表示しません。消えたラインは元のミノの色の小さな光と星になり、約0.7〜1.1秒かけて浮かんで消えます。演出中も次のミノを操作できます。端末の「視差効果を減らす」などの設定ではパーティクルを省略します。

右上の「マイページ」内の「スキン」でクラシック・半透明のクリスタル・メタルを選べます。盤面とHOLD・NEXTに反映し、選択はブラウザーに保存します。スキンは自分の画面だけに適用し、判定や対戦相手の設定には影響しません。

### GitHub Pagesへの公開

```bash
npm ci
npm run build
```

生成された `dist/` が配信物です。相対パスでビルドするため `/tetris/` のようなサブディレクトリでも動作します。

[Pages用GitHub Actions](.github/workflows/pages.yml)を用意しています。

1. GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. 変更を `main` にpushするか、Actionsから **Deploy to GitHub Pages → Run workflow** を実行します。
3. デプロイ結果に表示されるHTTPSのURLを両者で開きます。

このリポジトリが `ikkungames110/tetris` の場合、通常の公開先は `https://ikkungames110.github.io/tetris/` です。実際の公開先はPagesの設定画面を確認してください。独自ドメインを設定する場合は、その設定に従います。

ローカル確認は `npm run dev`、ビルド結果の確認は `npm run preview` です。どちらも対戦用のゲームサーバーは起動しません。[ViteのGitHub Pages配信手順](https://vite.dev/guide/static-deploy.html#github-pages)

### 外部サービスと接続できない回線

「自分でサーバーを運用しなくてよい」構成です。接続を始めるための情報交換には **PeerJS Cloud**、NAT越えの接続候補の発見には **STUN** を利用します。接続後のゲームデータはWebRTCで送受信し、PeerJS Cloudへ盤面や入力を送りません。仲介サービスの停止・制限時には、新規接続や再接続ができない場合があります。[PeerJS公式](https://peerjs.com/client/getting-started)

携帯回線・企業ネットワークなど、P2Pの直接接続ができない組み合わせでは **TURN中継サービス** が必要です。利用するサービスのTURN URL・ユーザー名・パスワードを、ルーム参加前の「接続できない場合のTURN設定」へ双方で入力してください。認証情報は保存せず、招待リンクにも含めません。サービス側で発行する期限付きの認証情報を使い、共用の長期パスワードを公開リポジトリやビルドへ埋め込まないでください。TURN使用時は対戦データが中継されます。[WebRTCのTURN説明](https://webrtc.org/getting-started/turn-server)

デフォルトではTURNを設定していないため、すべての回線での接続は保証できません。接続仲介サービスも使わない方式にする場合は、長い接続情報を両者で手動交換するUIが別途必要です。

P2Pではホストが判定を持つため、ホストの改変に対する公平性は保証しません。招待対戦と小規模なランダムマッチングを対象としています。ホスト交代、永続戦績、オンラインリプレイ、レート・地域別マッチングは未実装です。

### 接続仲介の設定（開発者向け）

既定はPeerJS CloudのHTTPS接続です。独自の仲介先を使う場合は、ビルド前に `VITE_PEER_HOST`、`VITE_PEER_PORT`、`VITE_PEER_PATH`、`VITE_PEER_SECURE` を設定できます。`VITE_STUN_URL` でSTUNを変更できます（`none` は同一マシンのテスト用）。これらの `VITE_` 設定は公開されるため、秘密情報を入れないでください。

ブラウザーテストでは開発用PeerServerをlocalhostで起動し、実際のWebRTCで対戦します。ゲームサーバー・外部の仲介サービス・外部STUNへ接続せずに検証できます。

以前のWebSocketゲームサーバーは `apps/server` に残していますが、標準の画面はP2P接続を使用します。`npm start` のNodeサーバーはGitHub Pagesへの配信には不要です。

## 遊び方

- 「エンドレス」ではおじゃまを受けずに、ゲームオーバーまで遊べます。
- 「40LINE」では40ライン以上を消すまでのタイムを計測します。カウントダウンと一時停止を除いたゲーム内時間をミリ秒表示（判定は60Hz）し、最後のライン消去で停止します。
- 対戦は「オンライン対戦」で招待ルームまたはランダムマッチングを使います。
- 「操作設定」で自分のキーボード／ゲームパッドを選びます。パッドは接続時に自動で選択されます。
- エンドレス・40LINEではEsc / Start / Menuで一時停止・再開。画面が非アクティブになったとき、使っているパッドが切断されたときも一時停止します。
- 「終了」でモード選択へ戻れます。「はじめから」は現在のゲームをリセットします。エンドレス・40LINEではパッドのB8（ボタン番号8）を1秒長押ししてもリセットでき、ミノ順・盤面・タイムが新しくなります。再リセットには一度ボタンを離してください。オンライン・リプレイ再生・操作設定中には無効です。
- エンドレス・40LINEの入力を「リプレイ保存」でJSONに保存し、「リプレイ再生」で再生できます。以前のローカル対戦リプレイも再生できます。

### ゲームパッド

DualShock / DualSense、Xbox、Switch Proなど、ブラウザーのGamepad APIで認識するパッドを使用できます。OSにUSBまたはBluetoothで接続し、パッドのボタンを一度押してください。ゲーム中に接続した場合も、自分の操作へ自動で割り当てます。既に別のパッドを使っている場合は切り替えず、「操作設定」から選択できます。

| 操作                   | 標準の割り当て              |
| ---------------------- | --------------------------- |
| 左 / 右移動            | 十字キー ← / →              |
| ソフトドロップ         | 十字キー ↓                  |
| ハードドロップ         | 十字キー ↑ / 右側の上ボタン |
| 左回転                 | 右側の下・左ボタン          |
| 右回転                 | 右側の右ボタン              |
| HOLD                   | 左右の肩ボタン              |
| 開始 / 一時停止 / 再開 | Start / Menu / OPTIONS      |

標準マッピングではメーカーのボタン名によらず物理的な位置で操作します。標準マッピングのないUSBパッドにも汎用の初期配置（ボタン0〜、方向は軸0/1）を割り当てます。異なる配置は「操作設定」でボタン・軸・hatを変更できます。保存した変更は次回も維持します。標準配置の左スティック移動は設定から有効にでき、スティック上ではハードドロップしません。[W3C Gamepad API・標準配置](https://www.w3.org/TR/gamepad/#remapping)

ブラウザーテストは各パッド相当の入力を模擬しています。実物のUSB/Bluetooth接続、OSやブラウザーによる差異は未検証です。

## ルールと実装範囲

SRS（I専用キック含む）、7-bag、HOLD、NEXT 5、ゴースト、DAS/ARR、接地猶予、T-Spin/Mini、B2B、更新後REN表、全消し、FIFO相殺、受信保留、おじゃま、top-out、ラウンド戦を実装しています。

原作と未照合のタイミング・境界条件は、[ゲームルール](docs/game-rules.md)の暫定値です。完全互換を保証するものではありません。実装の区切りと未実装項目は[実装状況](docs/implementation-status.md)を参照してください。

オンライン対戦はローカルと同じエンジンをホストのブラウザーで実行し、盤面・攻撃・勝敗を確定します。アカウント、CPUはまだ実装していません。

## 操作SEの候補

6用途（設置・回転・T-spin回転・通常消去・T-spin消去・4LINE消去）について、木琴・ベル・電子音の各3案、計18個のMP3を制作しました。[SE試聴室](https://tetcla.shianstudio.com/se-preview/)で比較・ダウンロードできます。ローカルでは `/se-preview/index.html` を開いてください。通常回転は03・08・10を選択でき、その他の用途はAを採用しています。Perfect clear用の1.8秒SEも試聴できます。[設計と再生成方法](docs/sound-design.md)を参照してください。

回転音を幅広く見直した[新しい10案の試聴室](https://tetcla.shianstudio.com/rotation-preview/)を追加しました。木玉・水滴・泡・アナログシンセ・FMエレピ・チップ音・ナイロン弦・シェイカー・陶器・和音シンセを、単発と連続回転で比較できます。[設計の違い](docs/rotation-sound-studies.md)も記録しています。
