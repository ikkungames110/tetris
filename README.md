# テトクラ — Tetcla

ブラウザーで遊べるオンライン対戦ブロックパズルです。現在は **ゲスト／ユーザー名ログイン・ユーザー別40LINE自己ベスト・ランダム対戦の戦績・エンドレス・40LINE・招待ルーム／ランダムマッチングでのオンライン対戦・ゲームパッド／タッチ入力** に対応しています。

公開版: **[https://tetcla.shianstudio.com/](https://tetcla.shianstudio.com/)**

### AI対戦

「AI対戦」タブを開き、盤面上でレベルを選ぶと、APIを使わずブラウザー内で動くAIとの対戦が始まります。本数制限はなく、勝敗表示のあと何度でも次の対戦へ進みます。スマホでは「AIの強さ」と「やり直す」を盤面左に配置しています。現在のミノとNEXTの2個を先読みし、消去ラインと配置後の地形を合わせて評価します。4LINESを高く評価しつつ、上が塞がった穴、深すぎる溝、複数の細い溝や2列幅の深い隙間、高さの積み上がりを避けます。探索候補を絞って操作速度を保ち、決定した手順は盤面の変化や自然落下でずれた場合に見直します。高さが10段以上になると、おじゃまを含む穴の上のブロックを掘り、少ないライン数でも消して地形を低くすることを優先します。6段以下まで下がると4LINES狙いに戻ります。盤面の穴・高さ・段差も評価する積み方は全レベル共通で、移動・回転・ドロップの操作間隔のみを8段階（500 / 300 / 約167 / 100 / 50 / 約33 / 平均25 / 約17 ms。レベル6はレベル5の1.5倍、レベル7は2倍、レベル8は毎フレーム操作する3倍の速度）で変更します。強さは対戦中にも変更できます。ミノ・回転・自然落下・固定・おじゃま・勝敗判定は通常の対戦と同じ処理を使います。

ランダム対戦のマッチングを開始したとき、またはルームに入室したときは、その画面で一人用のエンドレスが自動で始まります。マッチングは継続し、対人戦の開始時には新しい対戦盤面へ自動で切り替わります。ルーム対戦では通常どおり双方が「準備完了」を押してください。待機中にゲームオーバーになってもリスタートでき、検索の再試行では盤面を維持します。待機中のエンドレスとAI戦はレート・オンライン戦績の対象外です。

### 広告

PC・スマホともにi-mobile広告の表示・配信リクエストを有効にしています。

PCでは左右の160×600広告（左asid: `1943446`、右asid: `1945424`）に加え、画面最下部に320×50バナー（左asid: `1944749`、右asid: `1945423`）を2枠横並びで表示します。広告領域を確保した残りの高さにゲームを収めます。PCの4枠はpid: `85394`、mid: `596128`を共通で使用し、asid・elementidは枠ごとに異なる値を指定します。各タグは独立したiframe内で実行し、個別に配信をリクエストします。広告内容は配信側が選ぶため、同じ内容になることもあります。

スマホは画面最下部に320×50バナーを1枠だけ表示します（pid: `85394`、mid: `596133`、asid: `1943447`、elementid: `im-79fdebb4d3e248a6a9efc2b27ba13d85`）。PC用広告は読み込みません。ゲーム開始やモード変更では広告を再読み込みしません。

広告が届かない間は、サイト側の仮表示「広告配信待ち」を出します。配信用iframeまたは画像リンクが挿入されると仮表示を消します。広告の内容と配信開始時期はi-mobile側の設定・審査・配信状況に依存します。

### スマホ操作

幅760px以下、またはタッチを主な入力とする幅1100px以下の端末では、自動でスマホ用レイアウトに切り替わります。縦向きでは盤面の下、横向きでは盤面の左右の下部に操作ボタンが表示されます。

- 左側の十字キー：左右で移動、下でソフトドロップ、上でハードドロップ。
- 十字キーの左上：HOLD。
- 右側：左回転と右回転。

長押し移動と複数の指での同時操作に対応し、指のキャンセル・画面回転・タブ切り替えでは押下状態を解除します。タッチ操作はエンドレス・40LINE・オンライン対戦で利用でき、リプレイにも記録されます。PCのキーボード／ゲームパッドも引き続き利用できます。

## 起動

Node.js 24 LTS推奨（最低22.12）。

```bash
npm ci
npm run dev
```

[http://localhost:5173](http://localhost:5173) を開くと、エンドレスがすぐに始まります。40LINEはモードを選んで「プレイする」を押します。ゲームパッドは **localhost または HTTPS** で使ってください。別端末からHTTPのLANアドレスで開くと、ブラウザーの制限によりゲームパッドを取得できない場合があります。

WSLで作業する場合は、Node.jsとnpmもWSL側にインストールしてください。Windows側のnpmが呼ばれると、`CMD.EXE`のUNCパスエラーや`vite`が見つからないエラーで起動できません。WSLのターミナルで次を確認できます。

```bash
command -v node npm  # 両方ともLinux側のパスであること（/mnt/c/... はWindows側）
node -p 'process.platform'  # linux
```

Node.jsをインストールした直後も以前のnpmが呼ばれる場合は、`hash -r`を実行するか、WSLのターミナルを開き直してください。Windows側のnpmを使っていた場合は、WSL側で`npm ci`を実行して依存関係を入れ直してから`npm run dev`を実行します。`Port 5173 is already in use`なら、すでに起動しているゲームを上記URLで開くか、そのサーバーを停止してから再実行してください。

```bash
npm run build     # 型チェック＋配信用dist生成
npm run preview   # ビルドしたゲームを確認
```

## アカウント・40LINE自己ベスト（Cloudflare）

Cloudflare Pages → Pages Functions → API Worker → D1 の構成です。アクセス時はゲストになり、「ログイン」から新規登録・ユーザー名／パスワードでのログインができます。メールアドレスは不要です。ユーザー名はマイページで変更でき、変更後のログインにも新しい名前を使います。40LINEをクリアすると検証済みタイムを保存します。マイページで最速タイムとランダム対戦の対戦数・勝利数・勝率、現在・最高レートを確認できます。レートは1000開始で、双方ログイン時だけ増減します。ランダム対戦は3本先取で決着した試合と、対戦中の切断・退室による敗北を集計します。待機キャンセルとルーム対戦は含めません。ゲストの記録と戦績は新規登録時に引き継ぎますが、過去の未記録の対戦は遡って集計できません。[レートの計算式・切断判定](docs/rating.md)を参照してください。

アカウントAPIは初回表示時（セッション復元）に1回、ログイン・新規登録・ログアウト時に各1回呼び出し、その応答を画面間で共有します。マイページ・設定・ランキングの開閉やタブ切り替えでは再取得しません。40LINEは自己ベスト更新時だけPOSTします。ランダム対戦の結果とレートはサーバーが両者分をまとめて保存し、クライアントは決着通知後に1回POSTして記録表示を更新します。表示の取得に失敗した場合は再取得ボタンを使えます。切断側や他の端末の更新は、ページの再読み込み・再ログインでも反映されます。

全国ランキングはマイページの隣から開き、上部の40LINE／ランダム対戦タブで切り替えます。上位10人と自分の順位を表示します。40LINEはゲストを含むクリア記録、ランダム対戦は会員の現在レートが対象です。同記録は同順位（1位・1位・3位）とし、同順位内は40LINEでは達成日時・ユーザーID順、レートではユーザーID順に最大10人を表示します。表示名は対戦と共通です。

順位は起動時のセッション取得とログイン・新規登録・ユーザー名変更の応答に同梱し、記録保存・対戦終了・ログアウトでは再計算しません。ログアウト時には自分の順位表示を消し、公開一覧を保持します。最新の順位は再読み込み・再ログインで反映します。DBに順位検索用インデックスを追加し、上位10人と自分より良い記録の件数を取得します。全員分の順位表の定期再作成は行いません。

コントローラーのボタン割り当ては引き続きブラウザー内に保存するため、変更時のAPI通信はありません。

APIもローカルで試す場合は、`npm run db:local`、`npm run dev:api`を実行し、別ターミナルで`npm run dev`を起動します。Cloudflareへの公開・DB作成・GitHub Secrets設定・API仕様は[Cloudflareアカウント機能](docs/cloudflare-accounts.md)を参照してください。

GitHub Pages単体の配信はゲームのみです。既存のPagesワークフローでは`VITE_ACCOUNTS_ENABLED=false`を設定し、APIのない公開先にログイン画面を表示しません。Cloudflare用ビルドではアカウント機能が既定で有効です。

## オンライン対戦

ルーム対戦はWebRTC DataChannelでブラウザー同士を接続し、作成者のブラウザーが共通エンジンを60Hzで実行します。ルーム一覧とパスワードの確認にはCloudflare APIを使います。APIのないGitHub Pages版では招待リンクによるパスワードなしの対戦のみ利用できます。Cloudflare版のランダム対戦はサーバー（Durable Objects）で判定・切断処理・結果保存を行います。

1. 「ルーム対戦」→「ルームを作成」を選び、先取本数・ハンデ・パスワードの有無を設定して「作成する」を押します。パスワードありの場合は4桁の半角数字（先頭の0も可）を入力します。ハンデは「なし」、または1P（作成者）／2P（参加者）のどちらかを選び、各消去で送るライン数を−1〜−3ラインに設定できます。相殺後の送信ライン数から差し引き、最低0ラインです。双方に設定を表示し、次ラウンド・再戦でも維持します。
2. 相手は「ルーム対戦」を開き、最初から表示される「ホスト名・パスワード有無・何本先取」の表から、ホスト名を押して部屋を選びます。一覧は初めてルーム対戦を開いたときと「読み込み」を押したときだけ取得します。モードを開き直したり、ルーム作成画面から戻ったりしても再取得しません。取得は15秒に1回までで、ボタンに次の更新までの残り秒数を表示します。一覧を開き直しても待ち時間は維持します。待機中のホストは1分に1回掲載を更新し、更新が150秒途切れた部屋は一覧から消えます。入室後・退室時は掲載を取り下げます。
3. パスワードありの部屋では4桁を入力し、「参加する」を押します。パスワードはAPIで確認し、ホストでは検証しません。一覧には接続用コードを返しません。招待リンクも引き続き利用できます。双方が「準備完了」を押すと開始します。ランダム対戦の待機・対戦人数は、人数管理用の定期リクエスト増加を避けるため表示しません。
4. ランダム対戦は3本先取、ルーム対戦は作成時に1〜9本から選択します。各ラウンドの決着は、最終盤面のおじゃま上昇後にWIN / LOSEを表示し、3秒後に次ラウンドのカウントダウンへ進みます。指定本数の決着時だけ結果ダイアログを表示します。
5. ルーム対戦は決着後も同じ招待コード・参加者・設定を維持し、双方の「準備完了」で再戦します。「ルームで待機」やEscで結果を閉じても退室しません。ランダム対戦の「次の相手を探す」は新しくマッチングします。放置時間やアプリの無通信だけで接続を切ることはありません。実際の回線切断・退室は従来どおり扱います。

自分の盤面は左、相手は右に表示します（スマホの対戦中は自分を大きく、相手を右側に縮小表示）。盤面下には表示名と獲得本数の星を出します。会員の表示名はユーザー名（最大40文字）、ゲストは「ゲスト」です。一人用では盤面自体を画面の中央に配置し、盤面下の名前は表示しません。一時停止と40LINEの開始操作は盤面右側にあります。一人用ではINCOMINGを表示せず、エンドレスではタイムも表示しません。40LINEのタイムと自己ベストも盤面右側に表示します。

各端末では **操作設定の「自分の操作」** のキーボード／パッドを使います。参加者も自分の画面では左の盤面を操作します。**ホストは対戦中、このタブを前面で開いたままにしてください。** ホストのPCのスリープやブラウザーの停止は試合の進行に影響します。ホストがページを更新・終了すると試合は復元できません。参加者は接続が切れた後、ホストが残っていれば10秒以内に自動再接続／同じタブの再読み込みで復帰できます。

### ランダムマッチング

「ランダム対戦」を開くと現在・最高レートと「マッチング開始」を表示します。ボタンを押して初めて相手を探し始め、組み合わせが決まると自動で対戦を始めます。コード入力・準備完了ボタンは不要です。「キャンセル」で待機を取り消せます。ランダム対戦は常にハンデなしです。

待機中のブラウザーが共有の仲介IDを取得し、次の参加者がそこへP2P接続して対戦コードを交換します。対戦開始後は待機用IDを解放して次の組を受け付けます。Cloudflare版のゲームデータはWebSocketでAPI Worker配下のDurable Objectと送受信します。初期レートは1000、現在はレート差に関係なくマッチングします。ゲストも対戦できますが、片方がゲストなら双方のレートは変動しません。試合中の各盤面と結果画面にもレートを表示します。

待機中の盤面にはRajdhani Boldで「waiting for match...」を表示します。開始前・待機中はREADY、準備完了の案内、盤面下の名前・統計を出しません。検索に時間制限はなく、待機中に通信が切れた場合も自動で接続し直し、キャンセルするまで相手を探し続けます。相手の探索では地域・待ち順を保証しません。仲介サービスや相手とのP2Pコード交換が使えない場合は成立しません。必要な回線ではTURNを設定してください。仲介IDの指定・衝突・解放は[PeerJSのAPI](https://peerjs.com/client/api/peer)を使っています。APIのないGitHub Pages版はレートなしのP2P対戦です。

### 開始カウントダウン

3・2・1の間は移動・回転・HOLD・ドロップなどで盤面を操作できません。カウント中に押して離した入力は捨て、開始時点で押し続けているキー・ゲームパッド・タッチの操作は開始直後に反映します。ポーズ操作は持ち越しません。40LINE・オンライン対戦の各ラウンドに適用します。エンドレスはカウントダウンなしで始まります。

### 操作の遅延と描画負荷

参加者の移動・回転・HOLD・ドロップは、通信の返答を待たずに手元で先行表示します。ホストから届く確定状態と処理済み入力番号（ACK）で補正し、未処理の操作だけを再適用します。判定はホストに集約し、未公開のNEXTやおじゃまの穴は推測しません。その場合は確定状態を待つため、回線状況によって補正や待ちが発生します。

ホストは60Hzで表示を更新し、参加者への状態配信は通常30Hzです。盤面を短い文字列へ変換して通信量を減らし、変化のない盤面・HOLD・NEXTは再描画しません。エンドレス・40LINEは手動で再開できます。

消去時の文字はT-SPIN系（Miniは「T spin mini」）・4ライン同時消去の「4LINES」・全消しの「PERFECT CLEAR」を盤面上部に小さめ・半透明で表示します。中心から最大24pxの範囲で移動しながら、完全に透明な状態からフェードインし、消える時は逆にフェードアウトします。全消しは他の消去表示より優先します。通常の1〜3ライン消去・B2Bの文字は盤面に表示しません。連続消去はHOLDの下に2 RENから表示し、文字サイズを固定して5 RENごとに緑・黄色・赤・虹へ色を変え、軽く浮かぶフェードで表示します。消えたラインは元のミノの色の小さな光と星になり、約0.7〜1.1秒かけて浮かんで消えます。演出中も次のミノを操作できます。端末の「視差効果を減らす」などの設定ではパーティクルを省略します。

`src/templete`のJSONに、連携の各状態とTミノの設置位置を定義しています。DT canon、Double dagger、Houndstooth、Imperial cross、STSD、TD attackに対応し、指定位置・行のFull T-spinを順番に成立させると、最後の消去でテンプレート名と専用ボイスを出します。毎設置で形を確認し、別の行の消去による位置のずれや左右反転にも対応します。[各連携の消去行・検知条件・追加手順・ブラウザーでの速度計測](docs/templates.md)を参照してください。

右上の「マイページ」内の「スキン」でクラシック・半透明のクリスタル・メタルに加え、案3「ネオン／グロー」・案4「テクスチャ」・案5「ライン＆内部パターン」を選べます。すべてのスキンにセルの区切りがあり、模様は各セル内で完結します。同じ種類のミノが隣接しても模様は連結しません。

配色は従来の色を使い、盤面右側（NEXTの下）のバーで彩度・透明度を0〜100%に調整できます。彩度100%が元の色、0%が無彩色です。透明度0%が元の表示、100%が完全に透明です。盤面・HOLD・NEXT・7種類のプレビューに即時反映し、選択はブラウザーに保存します。スキンは自分の画面だけに適用し、判定や対戦相手の設定には影響しません。

### GitHub Pagesへの公開

```bash
npm ci
npm run build
```

生成された `dist/` が配信物です。相対パスでビルドするため `/tetris/` のようなサブディレクトリでも動作します。

[Pages用GitHub Actions](.github/workflows/pages.yml)を用意しています。

1. GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. 変更を `main` にpushするか、Actionsから **Deploy to GitHub Pages → Run workflow** を実行します。
3. デプロイ結果に表示されるHTTPSのURLを両者で開きます。

このリポジトリが `ikkungames110/tetris` の場合、通常の公開先は `https://ikkungames110.github.io/tetris/` です。実際の公開先はPagesの設定画面を確認してください。独自ドメインを設定する場合は、その設定に従います。

ローカル確認は `npm run dev`、ビルド結果の確認は `npm run preview` です。どちらも対戦用のゲームサーバーは起動しません。[ViteのGitHub Pages配信手順](https://vite.dev/guide/static-deploy.html#github-pages)

### 外部サービスと接続できない回線

「自分でサーバーを運用しなくてよい」構成です。接続を始めるための情報交換には **PeerJS Cloud**、NAT越えの接続候補の発見には **STUN** を利用します。接続後のゲームデータはWebRTCで送受信し、PeerJS Cloudへ盤面や入力を送りません。仲介サービスの停止・制限時には、新規接続や再接続ができない場合があります。[PeerJS公式](https://peerjs.com/client/getting-started)

携帯回線・企業ネットワークなど、P2Pの直接接続ができない組み合わせでは **TURN中継サービス** が必要です。利用するサービスのTURN URL・ユーザー名・パスワードを、ルーム参加前の「接続できない場合のTURN設定」へ双方で入力してください。認証情報は保存せず、招待リンクにも含めません。サービス側で発行する期限付きの認証情報を使い、共用の長期パスワードを公開リポジトリやビルドへ埋め込まないでください。TURN使用時は対戦データが中継されます。[WebRTCのTURN説明](https://webrtc.org/getting-started/turn-server)

デフォルトではTURNを設定していないため、すべての回線での接続は保証できません。接続仲介サービスも使わない方式にする場合は、長い接続情報を両者で手動交換するUIが別途必要です。

P2Pではホストが判定を持つため、ホストの改変に対する公平性は保証しません。Cloudflare版のランダム対戦はサーバーが入力から結果を判定し、永続戦績とレートを保存します。ホスト交代、オンラインリプレイ、レート・地域別マッチングは未実装です。

### 接続仲介の設定（開発者向け）

既定はPeerJS CloudのHTTPS接続です。独自の仲介先を使う場合は、ビルド前に `VITE_PEER_HOST`、`VITE_PEER_PORT`、`VITE_PEER_PATH`、`VITE_PEER_SECURE` を設定できます。`VITE_STUN_URL` でSTUNを変更できます（`none` は同一マシンのテスト用）。これらの `VITE_` 設定は公開されるため、秘密情報を入れないでください。

ブラウザーテストでは開発用PeerServerをlocalhostで起動し、実際のWebRTCで対戦します。ゲームサーバー・外部の仲介サービス・外部STUNへ接続せずに検証できます。

以前のWebSocketゲームサーバーは `apps/server` に残していますが、標準の画面はP2P接続を使用します。`npm start` のNodeサーバーはGitHub Pagesへの配信には不要です。

## 遊び方

- 「エンドレス」ではおじゃまを受けずに、ゲームオーバーまで遊べます。
- 「40LINE」では40ライン以上を消すまでのタイムを計測します。カウントダウンと一時停止を除いたゲーム内時間をミリ秒表示（判定は60Hz）し、最後のライン消去で停止します。
- 対戦は「オンライン対戦」で招待ルームまたはランダムマッチングを使います。
- 「操作設定」で自分のキーボード／ゲームパッドを選びます。パッドは接続時に自動で選択されます。
- エンドレス・40LINEではEsc / Start / Menuで一時停止・再開。画面が非アクティブになったとき、使っているパッドが切断されたときも一時停止します。
- 一人用では終了操作なしで、プレイ中・一時停止中も上部のボタンから別のモードへ切り替えられます。エンドレスはページを開いた時とモード選択時にすぐ始まり、スタート・終了ボタンはありません。40LINEの「はじめから」は現在のゲームをリセットします。エンドレス・40LINEでは盤面右側に長押し案内を表示します。パッドのB8（DualShock 4ではSHARE）、キーボードのR、または案内ボタン自体を1秒長押しするとリスタートでき、ミノ順・盤面・タイムが新しくなります。Rを別の操作に割り当てている場合はBackspaceを使い、両方割り当て済みの場合は案内ボタンで操作します。再リスタートには一度ボタンを離してください。ゲームオーバー時は盤面上に赤い「GAME OVER」と「リプレイを保存」「リスタート」を表示します。オンライン・リプレイ再生・操作設定中には無効です。
- エンドレス・40LINEの入力をマイページの「リプレイ保存」でJSONに保存し、同じ画面の「リプレイ再生」で再生できます。読み込み後は盤面へ戻り、進行中の一人用ゲームを置き換えて再生します。以前のローカル対戦リプレイも再生できます。

### キーボード

| 操作            | キー      |
| --------------- | --------- |
| 左 / 右移動     | ← / →     |
| ソフトドロップ  | ↓         |
| ハードドロップ  | Space / ↑ |
| 左 / 右回転     | Z / X     |
| HOLD            | 左Shift   |
| 一時停止 / 再開 | Esc       |

「設定」→「コントローラー」で「自分の操作」にキーボードを選ぶと、各操作のキーを変更できます。変更したい操作を選んでキーを押してください（Escでキャンセル）。同じキーを複数の操作には割り当てられません。変更はブラウザーに保存され、次回も維持します。「標準の割り当てに戻す」で上記の初期配置に戻せます。

### ゲームパッド

DualShock / DualSense、Xbox、Switch Proなど、ブラウザーのGamepad APIで認識するパッドを使用できます。OSにUSBまたはBluetoothで接続し、パッドのボタンを一度押してください。ゲーム中に接続した場合も、自分の操作へ自動で割り当てます。既に別のパッドを使っている場合は切り替えず、「操作設定」から選択できます。

| 操作                   | 標準の割り当て              |
| ---------------------- | --------------------------- |
| 左 / 右移動            | 十字キー ← / →              |
| ソフトドロップ         | 十字キー ↓                  |
| ハードドロップ         | 十字キー ↑ / 右側の上ボタン |
| 左回転                 | 右側の下・左ボタン          |
| 右回転                 | 右側の右ボタン              |
| HOLD                   | 左右の肩ボタン              |
| 開始 / 一時停止 / 再開 | Start / Menu / OPTIONS      |

DualShock 4を認識した場合、ボタン0〜15は順に「×・〇・□・△・L1・R1・L2・R2・SHARE・OPTIONS・L3・R3・↑・↓・←・→」と表示します。設定の割り当て・入力確認・HOLD・リスタート案内にも同じ表記を使います。

標準マッピングではメーカーのボタン名によらず物理的な位置で操作します。標準マッピングのないUSBパッドにも汎用の初期配置（ボタン0〜、方向は軸0/1）を割り当てます。異なる配置は「操作設定」でボタン・軸・hatを変更できます。保存した変更は次回も維持します。標準配置の左スティック移動は設定から有効にでき、スティック上ではハードドロップしません。[W3C Gamepad API・標準配置](https://www.w3.org/TR/gamepad/#remapping)

ブラウザーテストは各パッド相当の入力を模擬しています。実物のUSB/Bluetooth接続、OSやブラウザーによる差異は未検証です。

### 音量と設定

BGMは表示50%を既定値とし、従来のメーター5%相当の音量で再生します。新しい100%は従来の10%相当です。旧既定値40%は新しい50%へ移行し、旧設定のミュートと音量10%以下の音の大きさは維持します（旧40%以外の10%超は新しい100%に収めます）。SEは従来の70%の音の大きさを、新しい既定値50%として表示します。0〜50%と50〜100%の二段階の直線で音量を調整し、100%の最大音量は従来どおりです。既存設定も実際の音量を維持して移行します。

ゲーム画面のフッターは表示しません。規約・プライバシー・ライセンスは設定と公開の文書ページから参照できます。

設定の右隣にある「ヘルプ」では、Tスピン・T spin mini、REN、リプレイの保存・再生、コントローラーのボタン割り当て、基本操作を説明します。一人用で開くと一時停止します。PCのQUICK CONTROLSは盤面の左側に表示し、現在のキー・ボタン割り当てに追従し、一人用のリスタート（1秒長押し）も案内します。40LINEクリア時の結果はタイムだけを表示し、モード選択・再挑戦のボタンを添えます。

### 連続消去（REN）

画面には実際の連続消去回数を表示し、2回続けて消すと2 REN、3回なら3 RENになります。内部の攻撃計算・リプレイ用カウントは初回0のまま維持します。消去なしでミノを固定すると途切れます。2 REN以上の間はHOLDのかなり下に数字とRENを一行で表示します。書体は同梱のRajdhani Boldで、数字は22px、RENの文字はその70%の大きさに固定します。桁が増えてサイド領域に収まらない場合だけ縮小し、盤面には重ねません。色は表示回数で2〜4 RENが緑、5〜9 RENが黄色、10〜14 RENが赤、15 REN以上が虹になります。最初は240msのフェードと4pxの浮き上がり、回数更新時は180msの控えめなフェードと2pxの浮き上がりで表示します。「視差効果を減らす」設定では移動せずフェードだけにします。

連続消去の効果音は1 RENごとに半音ずつ高くなり、最大1オクターブまで上がります。消去ボイス・回転音・設置音の音程は変えません。連続数は音声用イベントのメタデータとして対戦相手にも送り、既存リプレイの検証値には含めません。
