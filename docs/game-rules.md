# ゲームルール

[設計書一覧](README.md) / [調査・検証](research-and-validation.md)

対象は PPT2 の通常 VS、テトリス対テトリス。以下の処理順・データ構造は本プロジェクトの設計であり、原作の内部実装を示すものではない。

## 1. 盤面・座標・ミノ

表示盤面を横10列×縦20行とする。表示セル数は **公式確認（画面図を目視）**。内部には上側20行の非表示領域を設け、合計40行を保持する。非表示領域の高さと出現位置は **暫定**。天井付近の回転と敗北判定を、表示領域の配列外アクセスで代用しない。[PPT2 公式マニュアルの2人対戦画面](https://manual.sega.jp/puyopuyotetris2/img/wm_232.jpg)

- 盤面座標は右が `+x`、下が `+y`。表示範囲は `x=0..9, y=0..19`、非表示範囲は `y=-20..-1`。
- セルは `empty | I | J | L | O | S | T | Z | garbage`。判定には占有の有無、描画には種別を使う。
- 移動先の4セルすべてが盤面内・空きであれば移動できる。左右外壁・床・内部領域の上端外は衝突とする。
- 横一列10セルが埋まった行を同時に消し、その上の行を消去数だけ下へ詰める。個々のブロックを別々に落とす重力は使わない。
- 消去対象の判定には非表示領域も含む。この細部は実機照合する。

ミノの局所座標は次の初期形を使う。J/L/S/T/Z は3×3、I は4×4、O は4×3の枠で表す。`.` は空き、文字は占有セル。各行は上から下。

| 種別 | 初期形（`/` は改行）  | 回転中心    |
| ---- | --------------------- | ----------- |
| J    | `J../JJJ/...`         | `(1,1)`     |
| L    | `..L/LLL/...`         | `(1,1)`     |
| S    | `.SS/SS./...`         | `(1,1)`     |
| Z    | `ZZ./.ZZ/...`         | `(1,1)`     |
| T    | `.T./TTT/...`         | `(1,1)`     |
| I    | `..../IIII/..../....` | `(1.5,1.5)` |
| O    | `.OO./.OO./....`      | `(1.5,0.5)` |

通常の回転形はこの中心を使って生成する。O は占有4セルが動かないように扱う。O に J/L/S/T/Z のキック表を適用しない。

出現時はすべて向き `0`、局所枠の左上を `(3,-2)` とし、出現衝突を確認してから可能なら1行下へ移す案とする。HOLD から戻ったミノも同じ出現処理を通す。出現直後の落下、上側への救済移動の有無は **暫定** で、特に窒息寸前の挙動を照合する。

## 2. 回転法則: SRS

**共通モデル**。公開研究で使われている標準 SRS の90度回転・キックデータを採用する。PPT2 固有の境界条件は別途確認する。[Tetris with Few Piece Types, §2・Tables 2–3](https://arxiv.org/html/2404.10712v1#S2)

向きは `0 → R → 2 → L → 0` が右回転、逆順が左回転。1入力で180度回転する機能は設けない。

回転後の形を現在位置で試し、衝突する場合は下表の候補を左から順に試す。最初に衝突しない候補を採用し、すべて失敗なら元の位置・向きを保つ。**表の値は元位置からの変位であり、候補を順に累積しない。**

この表だけは数学座標の **右 `+x`、上 `+y`** を使う。盤面へ適用する際は `boardX += dx; boardY -= dy` とする。候補番号は `1..5`。T-Spin 用に採用番号を保存する。

### J / L / S / T / Z 共通

| 回転  | 候補1 | 候補2  | 候補3   | 候補4  | 候補5   |
| ----- | ----- | ------ | ------- | ------ | ------- |
| 0 → R | (0,0) | (-1,0) | (-1,+1) | (0,-2) | (-1,-2) |
| R → 0 | (0,0) | (+1,0) | (+1,-1) | (0,+2) | (+1,+2) |
| R → 2 | (0,0) | (+1,0) | (+1,-1) | (0,+2) | (+1,+2) |
| 2 → R | (0,0) | (-1,0) | (-1,+1) | (0,-2) | (-1,-2) |
| 2 → L | (0,0) | (+1,0) | (+1,+1) | (0,-2) | (+1,-2) |
| L → 2 | (0,0) | (-1,0) | (-1,-1) | (0,+2) | (-1,+2) |
| L → 0 | (0,0) | (-1,0) | (-1,-1) | (0,+2) | (-1,+2) |
| 0 → L | (0,0) | (+1,0) | (+1,+1) | (0,-2) | (+1,-2) |

### I 専用

| 回転  | 候補1 | 候補2  | 候補3  | 候補4   | 候補5   |
| ----- | ----- | ------ | ------ | ------- | ------- |
| 0 → R | (0,0) | (-2,0) | (+1,0) | (-2,-1) | (+1,+2) |
| R → 0 | (0,0) | (+2,0) | (-1,0) | (+2,+1) | (-1,-2) |
| R → 2 | (0,0) | (-1,0) | (+2,0) | (-1,+2) | (+2,-1) |
| 2 → R | (0,0) | (+1,0) | (-2,0) | (+1,-2) | (-2,+1) |
| 2 → L | (0,0) | (+2,0) | (-1,0) | (+2,+1) | (-1,-2) |
| L → 2 | (0,0) | (-2,0) | (+1,0) | (-2,-1) | (+1,+2) |
| L → 0 | (0,0) | (+1,0) | (-2,0) | (+1,-2) | (-2,+1) |
| 0 → L | (0,0) | (-1,0) | (+2,0) | (-1,+2) | (+2,-1) |

上の2表は SRS の数値データを実装用に整理したもの。回転中心からの形生成とキック処理を独立させ、I の左右非対称性も保持する。

## 3. 出現順: 7-bag

**実演資料／共通モデル**。I/J/L/O/S/T/Z を1個ずつ含む袋をシャッフルし、7個を取り出し終えてから次の袋へ進む。PPT2 の7種1巡はプレイヤーの実演で確認されている。[7種1巡の解説・実演](https://note.com/blueceru55/n/n053fc510e19b)

実装は次の方針とする。

- Fisher–Yates 法でシャッフルし、各位置の抽選は一様整数で行う。`sort(() => random() - 0.5)` は使わない。
- 決定的な整数 PRNG を採用し、アルゴリズム名・版・初期状態・袋の残り・消費位置をリプレイに保存する。原作の乱数そのものの再現は対象外。
- ミノ列生成とおじゃま穴生成は乱数ストリームを分離する。穴を何回抽選してもミノ列が変化しないようにする。
- 両者は同じミノ列を、それぞれの消費位置から使用する。この公平性の方針は **暫定** で、原作の対戦設定との照合対象。
- 最初の袋にも通常の7種を使用し、先頭ミノの制限は設けない **暫定** 仕様とする。
- ラウンドごとに袋、HOLD、REN、B2B、乱数状態を初期化する。

7-bag からの数学的な帰結として、袋の境界では同種が2連続することがあり、同種が出ない間隔は最大12個。これは「任意の連続7個が必ず7種類」という意味ではない。HOLD によって、実際に固定する順番は元のミノ列から変わる。

## 4. HOLD / NEXT / ゴースト

HOLD が1個で、使用中のミノと交換できることは **公式確認**。詳細な再使用条件や復帰時のタイマー処理は **暫定** とする。[PPT2 公式マニュアル、Tetris の Hold Queue](https://cdn.akamai.steamstatic.com/steam/apps/1259790/manuals/tenpex_WM_210216_Steam_en.pdf#page=7)

| 操作・状態                 | 初版の動作                                                  |
| -------------------------- | ----------------------------------------------------------- |
| 空 HOLD で押す             | 現在ミノを保存し、NEXT 先頭を消費して出現                   |
| 使用済み HOLD で押す       | 保存ミノと現在ミノを交換。NEXT は消費しない                 |
| 同じ固定区間でもう一度押す | 無視する。空 HOLD 後に出たミノでも連続 HOLD はできない      |
| ミノが固定された           | 次のミノから HOLD を再使用可能にする                        |
| HOLD から復帰              | 向き0・出現位置へ戻す。落下／接地タイマーと回転履歴を初期化 |
| 復帰したミノが衝突         | 出現時の敗北条件を適用                                      |
| NEXT                       | 未出現の先頭5個を上から順に表示。HOLD は別枠                |
| ゴースト                   | 現在ミノをそのまま真下へ落とせる最終位置を表示              |

NEXT 5個は **公式確認（画面図を目視）**。2人対戦画面の両盤面に5個ずつ表示され、HOLD が別枠であることを確認した。[PPT2 公式マニュアルの対戦画面](https://manual.sega.jp/puyopuyotetris2/img/wm_232.jpg)

入力は押下エッジで処理し、HOLD の押しっぱなしでミノごとに再交換しない。出現前の先行 HOLD／回転入力（IHS／IRS）は初版では無効とし、原作の受け付け方を実測する。

## 5. 操作タイミング

論理更新は60 Hz。`1 tick = 1/60秒` とし、描画 FPS と独立させる。ソフトドロップ・接地時硬直は実際に更新された項目であるため、一般的な値を「PPT2 の確定値」と呼ばない。[SEGA Ver.1.3.2 更新情報](https://puyo.sega.jp/puyopuyotetris2/information.html)

以下はすべて **暫定の初期調整値**。原作の計測結果ではない。

| パラメーター               | 初期値          | 意味                                             |
| -------------------------- | --------------- | ------------------------------------------------ |
| 自然落下                   | 60 ticks / cell | 最初は一定速度。対戦時間による加速は未実装       |
| DAS                        | 10 ticks        | 左右長押しから連続移動開始まで                   |
| ARR                        | 2 ticks / cell  | DAS 経過後の横移動間隔                           |
| ソフトドロップ             | 2 ticks / cell  | 自然落下より速い方を使う                         |
| 接地猶予                   | 30 ticks        | 接地してから自動固定まで                         |
| 接地猶予リセット上限       | 15回 / piece    | 有効な移動・回転による延長の上限                 |
| 固定後の出現待ち           | 0 ticks         | 次のtickで出現し、そのtickから操作可能           |
| ライン消去待ち             | 0 ticks         | 消去の文字表示中も次のミノを操作可能             |
| おじゃま演出による追加待ち | 0 ticks         | 原作の被弾硬直は要計測                           |

左右は押した瞬間に1セル動かし、長押しで DAS/ARR を適用する。左右同時は後から押した側を優先し、同一 tick の押下は中立とする。回転左右同時は相殺して回転なし。キーの OS リピートは使用しない。

固定前に可能な移動／回転が成功したときだけ接地猶予をリセットする。上限に達した後はそれ以上延長しない。キックで空中に出ても使用回数を保持し、再接地後に残り猶予を再開する。O の回転は占有セルが変わらないため、初版では猶予を延長しない。下段へ落ちた場合の猶予再設定、O 回転、空中での猶予扱いは実機照合する。

ハードドロップは着地位置まで動かして同 tick に固定する。`ppt2-vs-draft-2` では操作を止めないため、固定後・ライン消去後の待ち時間を廃止した。次の tick にミノを出現させ、その tick の移動・回転・HOLD・ドロップ入力を受け付ける。T-SPINなどの文字表示は操作と独立して継続する。1 tick に複数ミノを固定することは許可しない。旧版リプレイは記録時の待ち時間（固定後6 ticks、消去後30 ticks）で再生する。

同 tick の優先順位は `HOLD → 回転 → 左右移動 → ハードドロップ → ソフト／自然落下 → 接地タイマー`。HOLD が成立した tick はそこで操作を終える。これは入力競合を一定にする本プロジェクトの規約で、原作の順序とは未照合。

## 6. T-Spin と Mini の判定

T-Spin の存在・回転入れによる成立は **公式確認**。3隅判定と各技の攻撃量にはプレイヤーの実演資料がある。実装上の細部は以下の **暫定判定器** で固定し、FIN／NEO／ISO を含む盤面で照合する。[PPT2 公式マニュアル](https://cdn.akamai.steamstatic.com/steam/apps/1259790/manuals/tenpex_WM_210216_Steam_en.pdf#page=7)、[T-Spin 各種の図解・実演](https://note.com/blueceru55/n/n053fc510e19b)

1. T ミノが固定されたこと。
2. 最後に成功した位置・向きの変更が回転であること。
3. 回転中心の斜め4隅のうち3隅以上が占有されていること。
4. T の突起側の2隅が両方埋まっていれば通常 T-Spin、それ以外は Mini。
5. ただし、最後の回転が SRS の候補5で成立していれば通常 T-Spin へ昇格させる案とする。

判定は **ミノ固定後、ラインを消す前の盤面** を用いる。隅は中心 `(cx,cy)` に対し `(cx±1,cy±1)`。自分の T のセルは隅を占有しない。外壁・床は埋まった隅として数え、`y<0` も内部盤面が存在する範囲では実セルを調べる。

| 向き | 突起方向 | 前側2隅（下向き正の盤面座標） |
| ---- | -------- | ----------------------------- |
| 0    | 上       | 左上・右上                    |
| R    | 右       | 右上・右下                    |
| 2    | 下       | 左下・右下                    |
| L    | 左       | 左上・左下                    |

失敗した移動・回転入力は最後の成功操作を上書きしない。移動距離0のハードドロップは回転履歴を保ち、そのまま固定する。1セル以上落下した場合はソフト／ハード／自然落下とも回転履歴を解除する案とする。落下種別ごとの扱いは実機で確認する。

Mini Double を「2行消去だから通常 T-Spin」と自動昇格させない。NEO Double が Mini・基礎1ラインになる実演資料がある。T 以外の回転入れは通常のライン消去として処理し、All-Spin ボーナスは設けない。[NEO Double の実演説明](https://note.com/blueceru55/n/n053fc510e19b)

## 7. 攻撃ライン数

以下は **テトリス対テトリス用**。ゲーム内スコアの点数ではなく、相手に送るおじゃまの行数。基本火力、B2B、REN、Mini Double は更新後の PPT2 を扱う実演資料に基づく。[火力・REN・T-Spin の実演資料](https://note.com/blueceru55/n/n053fc510e19b)

### 基本火力

| 消し方                  | 消去行数 | 基本火力 | B2B 成立時（REN を除く） |
| ----------------------- | -------- | -------- | ------------------------ |
| 消去なし                | 0        | 0        | 0                        |
| Single                  | 1        | 0        | 対象外                   |
| Double                  | 2        | 1        | 対象外                   |
| Triple                  | 3        | 2        | 対象外                   |
| Tetris                  | 4        | 4        | 5                        |
| T-Spin / Mini、消去なし | 0        | 0        | 0                        |
| T-Spin Mini Single      | 1        | 0        | 1                        |
| T-Spin Mini Double      | 2        | 1        | 2                        |
| T-Spin Single           | 1        | 2        | 3                        |
| T-Spin Double           | 2        | 4        | 5                        |
| T-Spin Triple           | 3        | 6        | 7                        |

Mini Double の B2B 加算は一般規則からの初版の採用であり、実機で独立確認する。

### B2B: Back-to-Back

状態 `b2bActive` は初期 `false`。今回の消去が Tetris または行消去ありの T-Spin／Mini の場合、**直前の状態** が `true` なら今回 +1 し、状態を `true` にする。対象技を交互に使ってもよい。

通常の1〜3行消去で `false` にする。消去なしの固定では維持する。消去なし T-Spin も初版では開始・解除・追加攻撃をせず、現状維持とする。B2B の成立と「消去なし」の厳密な境界は実機検証対象。回数に応じた増幅は導入しない。

### REN（ユーザー記載の len に相当）

連続したミノ固定で毎回1行以上を消すと続く。初回消去を **0 REN**、2回目を1 RENと数える。消去行数ではなく「連続して消した固定回数 − 1」。HOLD・移動・時間経過では切れず、消去なしの固定で切れる。

| REN    | 連続消去回数 | 今回の追加火力 |
| ------ | ------------ | -------------- |
| 0〜1   | 1〜2回       | 0              |
| 2〜3   | 3〜4回       | 1              |
| 4〜5   | 5〜6回       | 2              |
| 6〜7   | 7〜8回       | 3              |
| 8〜12  | 9〜13回      | 4              |
| 13以上 | 14回以上     | 5              |

配列で表すなら `renBonus = [0,0,1,1,2,2,3,3,4,4,4,4,4,5]`、13以上は末尾の5を使う。これは累積火力の配列ではない。古い「11 RENから5」の表は初版に使わない。[公式の REN 調整告知](https://puyo.sega.jp/puyopuyotetris2/information.html)、[更新後の REN 表](https://note.com/blueceru55/n/n053fc510e19b)

実装では `ren=-1` で開始し、消去ありなら `ren += 1`、消去なしなら `ren=-1`。0 REN は内部で保持するが、画面の REN 表示は1以上で出す。

### Perfect Clear（全消し）

ラインを消した直後、非表示領域も含む全セルが空なら成立。おじゃまを受け入れる前に判定する。成立技の消去行数に依存せず10ラインという実演資料に合わせ、初版では **今回の攻撃合計を10に置き換える**。`通常火力 + 10` にしない。[全消しの実演説明](https://note.com/blueceru55/n/n053fc510e19b)

ただし、同時に REN／B2B が乗ったケースでの重複加算までは今回の資料だけで断定しない。置き換え規則は **暫定** であり、3条件を別々に実機比較する。REN と B2B の状態更新自体は、その全消しを発生させた消去内容に従って行う。通常 Double で全消しした場合、B2B は切れる案とする。

### 計算順と例

```text
消去前の盤面で spinKind を判定
ライン消去 → perfectClear 判定
ren 更新
b2bBonus = 今回が対象技 && 更新前b2bActive ? 1 : 0
b2bActive 更新
attack = 消去なし ? 0 : baseAttack + b2bBonus + renBonus[ren]
attack = perfectClear ? 10 : attack
cancelled = min(attack, 相殺可能な受信予告の総行数)
outgoing = attack - cancelled
```

| 状況                          | 今回の攻撃量（相殺前）           |
| ----------------------------- | -------------------------------- |
| B2Bなし・0 REN の TSD         | 4                                |
| Tetris → 消去なしで固定 → TSD | TSD は5。REN は0、B2B は維持     |
| TSD → 次ミノも TSD            | 2回目は5。1 REN の加算は0        |
| Single を3回連続              | 各0、0、1。合計1                 |
| Single を14回連続             | 13 REN時は5。累積37              |
| B2B中・4 RENで Tetris         | `4 + 1 + 2 = 7`                  |
| 受信予告3、B2Bなしの TSD      | 4のうち3を相殺、相手へ1          |
| 全消し、受信予告6             | 初版では10のうち6を相殺、相手へ4 |

## 8. おじゃま・相殺・受信タイミング

相殺と攻撃到達時刻の細部は未確定のため、以下を **暫定** の対戦規約とする。数値が同じでも、この順序が異なると対戦感は変わる。

受信キューは `attackId, createdTick, eligibleTick, remainingLines` を保持する。攻撃を作るのはサーバーのみ。予告到着と盤面へのせり上がりを別イベントにする。

1. ラインを消すごとに攻撃を確定する。REN が切れるまでまとめて送る方式にはしない。
2. 自分の受信予告を古い順に1対1で相殺し、余剰のみ相手へ送る。
3. 予告として登録済みなら、せり上がり待ち時間中も相殺できる。
4. `eligibleTick = createdTick + 30` とする初期案。30 ticks は実測値ではない。
5. 行消去ありの固定では残ったおじゃまをせり上げず保留する。攻撃力0の Single でも保留する。
6. 行消去なしの固定で、受信済みかつ `eligibleTick` 到達済みの行を下から追加する。
7. 1回の追加は最大8行とする初期案。残りはキューに残し、次の消去なし固定で再判定する。
8. HOLD、出現、単なる時間経過ではせり上がりを発生させない。

相殺時の待ち時間の扱い、ライン消去による保留、上限8行、被弾硬直は検証必須。対ぷよのゲージ・マージンタイムや別タイトルのおじゃま上限を、対象作品の確定値として扱わない。

### 穴位置の抽選

前作の実機検証には、**1回の受け入れ内は70%で前行と同じ穴、30%で異なる穴。別の受け入れの先頭は一様抽選** という報告がある。また、複数回の攻撃をまとめて受けた場合も1つの受け入れとして扱われる。これは PPT2 の計測ではないため **暫定継承** とする。[ぴーはちじーによる前作の実機検証](https://p8g.hatenablog.com/entry/2018/08/14/070957)

- せり上がる各行は9個のおじゃまセルと1個の穴。
- 受け入れの先頭行は10列から一様抽選。
- 2行目以降は70%で同列、30%で残り9列から一様抽選する。
- 30%の分岐で10列から引き直すと実際の穴変更率が27%になるので、その実装にしない。
- 相殺で完全に消えた行には穴を生成しない。穴の乱数は実際の受け入れ時に消費する。
- 最大8行で分割した次の受け入れは新たな先頭行として抽選する案。分割境界の挙動も確認する。

### 同時攻撃の処理

1 tick の処理は両者を同じ入力前状態から進め、両者の固定・消去・発生火力を一度収集してから解決する。

`既存の受信予告を相殺 → 今回の余剰を双方の受信キューへ追加 → 消去なし側の到達済み行を受け入れ → 敗北判定`

同 tick に生まれた双方の余剰攻撃同士は直接相殺しない案とする。サーバーが1Pから計算したから1Pだけ有利、とならないようにする。新規攻撃は待ち時間があるため同 tick にはせり上がらない。これも原作とは未照合の規約。

## 9. 敗北・ラウンド

公式資料は上まで積み上がる敗北を説明するが、細かな top-out 判定は十分公開されていない。以下は **暫定**。

| 条件               | 初版の扱い                                                              |
| ------------------ | ----------------------------------------------------------------------- |
| Block out          | 通常出現または HOLD 復帰時に4セルのどれかが既存セルと重なると敗北       |
| Lock out           | 固定ミノの4セルが、ライン消去と行詰め後も全て表示領域より上に残ると敗北 |
| Partial lock out   | 一部だけが表示領域より上なら、それだけでは敗北にしない                  |
| Garbage overflow   | せり上がりによって占有セルが内部40行の上端外へ押し出されたら敗北        |
| 同 tick の両者敗北 | 引き分け。勝利数を増やさず、新しい乱数でラウンド再開始                  |

Lock out では「今回固定した4セル」を追跡する。消去されたセルがある場合は上記の全4セル残存条件に当たらない。20行より上にセルがあるだけで即敗北とはしない。

初期ルームは2本先取・セット制なし・ハンデなし・カウントダウン3秒。各ラウンド開始時に盤面・乱数・HOLD・予告・タイマーを初期化する。開始前に押して離した入力は持ち越さず、開始時に押し続けているゲーム操作は開始直後に反映する。ポーズ操作は持ち越さない。

長時間戦の重力加速やマージン挙動は未確認。初期実装では攻撃倍率を一定とし、運用上の上限として1ラウンド10分で引き分けにする案とする。これは原作互換の時間制限ではなく、ルームに表示する本ゲームの規約。
