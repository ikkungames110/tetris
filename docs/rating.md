# ランダム対戦のレーティング

会員の初期レート・初期最高レートは1000。既存会員にも同じ初期値を設定し、過去の対戦からは計算し直しません。マッチングはレート差を一切制限しません。2本先取を1試合として扱い、ラウンドごとの加算はしません。

勝つと上がり、負けると下がる仕組みと切断負けの扱いは、[セガのぷよぷよテトリス2S公式マニュアル](https://manual.sega.jp/puyopuyotetris2/S/jp/)を参考にしています。同作の計算式を再現したものではありません。

## 計算式

試合開始時の敗者のレートから勝者のレートを引いた値を `d` とします。

```text
増減幅 = round(24 + 20 × d / (400 + abs(d)))
勝者の新レート = 現在レート + 増減幅
敗者の新レート = max(0, 現在レート - 増減幅)
最高レート = max(これまでの最高レート, 新レート)
```

同格では24点。400点上の相手に勝つと34点、400点下の相手に勝つと14点。独自の滑らかな有理関数で、格上への勝利ほど増加し、極端な差でも4〜44点の範囲に収まります。敗者が0点付近の場合は減少だけを0で止め、勝者の加点は維持します。連勝・圧勝・切断に追加係数は付けません。

両方が接続時にログイン済みの会員だった場合だけ増減します。片方でもゲストなら両者とも増減0で、最高レートとレート対象試合数も変わりません。ゲストはレートの代わりに `GUEST` を表示します。ルーム対戦はレート対象外です。

## 結果と切断

Cloudflare版のランダム対戦は、1部屋に1つのDurable Objectを割り当て、共通ゲームエンジンを60Hzで実行します。接続時のCookieから参加者を特定し、相手へ送る個人情報はレートだけです。クライアントは入力を送り、勝者・増減値を決められません。手元の入力予測とACKによる補正は引き続き使います。

- 2本先取の通常決着、カウントダウン・ラウンド間を含む対戦中の退室、WebSocket切断は結果を保存します。切断検知時に切断者が負けになります。無通信の検知は約6秒、切断後の復帰猶予はありません。
- 対戦前の待機キャンセルでは戦績・レートを変更しません。通常決着後の切断は勝者を変えません。
- サーバー停止・状態消失・サーバーの長い停止、両者の同時無応答は勝者を作らず無効とします。
- D1のバッチで両者の戦績、現在値、最高値、対象試合数をまとめて保存します。`(user_id, match_id)`と適用済みフラグで重複加算を防ぎ、同じアカウントの複数試合が重なっても古い値で上書きしません。
- 決着時の保存待ち情報はDurable Objectのストレージに置きます。D1障害時はalarmで再試行し、双方のタブが閉じた後も保存を続けます。未決着のゲーム状態は永続化しません。
- ブラウザーは確定通知後、`POST records/random`で自分の最新記録を取得します。このAPIでは勝者やレートを書き込めません。切断した側の記録もサーバーが更新し、再読み込み・再ログインで確認できます。

試合中は各盤面の右下に小さくレートを表示し、決着画面には両者の増減を表示します。マイページに現在・最高レートを表示します。

## 公開と互換性

`0003_ratings.sql`と`RandomRoom`のSQLite Durable Object migrationが必要です。既存のCloudflare公開ワークフローはDB migration→API→Pagesの順に適用します。追加の外部サービス契約やプラン変更は行いません。ゲーム中のDurable Objectは60Hzのタイマーで動くため、WebSocketを保持している間の実行時間が利用枠の対象です。[CloudflareのWebSocketの説明](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)

相手の探索・コード交換には従来のPeerJS仲介を使います。APIを持たないGitHub Pages版（`VITE_ACCOUNTS_ENABLED=false`）はP2Pのゲスト対戦で、レート・永続戦績を利用できません。通信プロトコルをv5に更新し、古いクライアントとは待機列を分けています。サーバー対戦とP2P対戦も別の待機列にして、通信方式が異なる相手との組み合わせを防ぎます。
