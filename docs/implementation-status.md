# 初回実装の状況

更新日: 2026-09-06 / アプリ版・エンジン版: `0.1.0` / ルール版: `ppt2-vs-draft-1`

今回の実装単位は[開発順](network-and-infrastructure.md)の段階1・2（練習とローカル対戦）を中心に、入力リプレイとゲームパッド対応を含むもの。ネット対戦・インフラ構築は次の段階とする。

## 実装済み

- 10×20表示・非表示20行、SRS90度回転、I専用キック、7-bag、HOLD 1個、NEXT 5個、ゴースト。
- 整数tickの落下、DAS/ARR、接地猶予とリセット上限、ドロップ、出現／消去待ち。
- T-Spin/Mini判定、候補5の昇格、Mini Double、B2B、13 REN以上で追加5行、全消し10への置換。
- 同tickに両者の固定を収集してから解決する攻撃処理、FIFO相殺、消去時の受信保留、8行受信上限、70/30穴生成。
- Block out、Lock out、部分Lock outの許容、内部領域overflow、同時敗北、2本先取とラウンド初期化。
- 1人練習／同端末2人対戦、リプレイ保存・読み込み・最終状態の検証。
- キーボード2系統、Gamepad APIの標準配置、DualShock 4用表示、ボタン変更・保存、デバイス割り当て。
- パッド切断／画面非アクティブ時の一時停止、押しっぱなしによる再発火防止、スティックのデッドゾーン。

## 初版で具体化した実装規約

| 項目             | 実装                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| PRNG             | `xorshift32-v1`。一様整数は棄却抽選。袋とおじゃまは別状態                             |
| 更新             | 渡された状態だけを書き換える。壁時計、DOM、外部乱数への依存なし                       |
| 入力             | プレイヤーごとに保持ビットと押下ビット。描画フレームとtick間で押下を保持              |
| Oの回転          | 占有セルを動かさず、接地猶予を延長しない                                              |
| 接地猶予の更新   | 移動・回転の直前に接地していた場合だけ延長。キックで空中へ出た間は残り時間を保持      |
| 操作フレーム落ち | 250 msを超える描画停止でローカルゲームを一時停止。大量の後追い入力を適用しない        |
| リプレイ         | ルール版・エンジン版・seed・ラウンドごとのRLE入力・最終状態ハッシュ。対応版以外を拒否 |
| リプレイの上限   | 読み込み5 MB、216,000 ticks、100ラウンド。初版では約1時間まで                         |
| 対戦終了         | 手動で次ラウンドへ進む。ゲーム間の待機時間はリプレイtickに含めない                    |
| ローカル切断     | 切断すると全体を一時停止。ネット対戦の「進行継続・10秒猶予」は適用しない              |

ゲームの大部分の数値は設計書の暫定値を実装したものであり、原作の実機検証が完了したという意味ではない。

## これから行うこと

1. 実物のDualShock 4で、対象OS・ブラウザーごとのUSB/Bluetooth接続を確認する。
2. [実機検証表](research-and-validation.md)に沿ってPPT2の操作フレーム数、T-Spin境界、全消しの重複加算、おじゃま・top-outを比較する。
3. 通信プロトコルとサーバー進行、招待ルーム、状態配信・入力予測と補正を実装する。
4. DBへの結果保存、リプレイ保管、切断・再接続、国内リージョンでの負荷試験へ進む。

## ゲームパッドの根拠と検証範囲

入力配置と取得方法は [W3C Gamepad API](https://www.w3.org/TR/gamepad/#remapping) を参照した。標準配置の右下・右・左・上のボタンをDS4の×・○・□・△として扱う。

ユニットテストでは標準ボタン、同時押し、スティックのヒステリシス、ボタン・軸・生のhat入力の割り当て、切断を検証する。ブラウザーテストでは `navigator.getGamepads()` にDS4相当の入力を供給し、ゲーム画面を操作する。これは実際のUSB・Bluetooth通信やOSのドライバー動作の試験ではない。
