# 実装の状況

更新日: 2026-09-07 / アプリ版・エンジン版: `0.1.0` / ルール版: `ppt2-vs-draft-2`

実装範囲は[開発順](network-and-infrastructure.md)の段階1・2と段階4（P2P招待ルームでのオンライン対戦）。ローカルの入力リプレイとゲームパッドにも対応。段階5の先行表示・ACK補正、Cloudflare上のアカウントと40LINE自己ベストの永続保存を実装・公開済み。

## 実装済み

- 10×20表示・非表示20行、SRS90度回転、I専用キック、7-bag、HOLD 1個、NEXT 5個、ゴースト。
- 整数tickの落下、DAS/ARR、接地猶予とリセット上限、ドロップ。固定・消去後の待ち時間はなく、文字表示中も操作可能。旧版リプレイの待ち時間は維持。
- T-Spin/Mini判定、候補5の昇格、Mini Double、B2B、13 REN以上で追加5行、全消し10への置換。
- 同tickに両者の固定を収集してから解決する攻撃処理、FIFO相殺、消去時の受信保留、8行受信上限、70/30穴生成。
- Block out、Lock out、部分Lock outの許容、内部領域overflow、同時敗北、2本先取とラウンド初期化。
- エンドレス・40LINE（40ライン消去までのタイム計測、カウントダウン・停止中を除外）、リプレイ保存・読み込み・最終状態の検証。
- 自分用のキーボード、Gamepad APIの標準・汎用配置、接続時のパッド自動割り当て、ボタン変更・保存、デバイス割り当て。
- ローカルのパッド切断／画面非アクティブ時の一時停止、押しっぱなしによる再発火防止、スティックのデッドゾーン。

- 6文字の招待コード・招待リンク、双方の準備完了、オンライン2本先取、結果3秒後の次ラウンド・再戦の自動開始。
- ホストのブラウザーによる60Hz判定・表示、通常30HzのP2P状態配信、入力と受信状態の検証。PeerJS Cloudによる接続仲介、任意のTURN設定。
- 自分の操作の先行表示、ACKによる未処理入力の再適用、盤面の文字列化、変更時だけのCanvas・テキスト更新。
- 消去表示はT-SPIN系・4ライン同時消去の「4LINES」・全消しの「PERFECT CLEAR」で盤面上部。Rajdhaniの文字がランダムな斜め方向から中央へ入り、一時停止後に反対側へ抜ける1.7秒の演出。cubic-bezierで加減速し、前後に3本ずつの細い線を添える。盤面内でクリップし周辺UIより奥に表示する。全消しを優先し、動きを減らす設定では移動と線を省略する。消えた行には従来の光の粒と星のパーティクルも表示する。
- Cloudflare版のランダム対戦はDurable Objectが共通エンジンを60Hzで実行し、切断側を敗北としてD1へ両者分の戦績を保存。会員は1000開始の独自レーティング、現在・最高レート表示に対応。片方がゲストなら両者とも変動なし。レート差でマッチングを制限しない。[計算式と保存の仕様](rating.md)。
- 参加者の通信切断後10秒復帰・同じタブの再読み込み、棄権。ホストの画面を閉じた場合の試合復元は非対応。
- GitHub Pagesへの静的配信ワークフロー、サブディレクトリ配置。以前のNode.jsサーバーは任意アダプターとして保持。

## BGM・SE・設定・スマホ操作

型チェック・ユニット115件・API9件・ビルド成功。Chromiumの51ケースを確認（一括実行では50件成功、40LINEの1件はテスト用APIのセッション作成回数制限で429となり、新しいテストDBで単独再実行して成功）。実音源のデコード、フェードの予約時刻、曲変更の競合、音量保存、320〜390pxの縦画面と844pxの横画面を検証。実機のSafari・ゲームパッドでの音声確認は未実施。

- `src/bgm` の9曲を収録。初期選択は「ピコピコディスコ」。ゲーム画面のプルダウンでいつでも曲を変更でき、ランダムループでは直前と異なる曲を選ぶ。
- BGMは曲末と次の冒頭を0.3秒重ねてクロスフェード。Web Audioの時刻で次の再生を予約し、次曲を先読みする。デコード済みBGMのキャッシュは直近2曲まで。
- 最初のタップ・キー操作から音声を開始。ヘッダーの「音 ON / OFF」で一括消音し、非表示タブでは音声を休止する。
- 設置・T-spin回転・通常消去・T-spin消去・4LINE消去はA（木琴）を採用。通常回転は設定の開発用セレクターで03・08・10を選択（初期値03、08は約3.8 dB減音）。選択を保存し、試聴ボタンを用意。T-Spin Mini／Single／Double／Tripleと4LINE同時消去は `src/se` のボイスも重ねる。Perfect clearは1.8秒の専用SEと追加ボイスを優先して同期再生。オンラインの確定イベントとリプレイにも対応。オンラインの相手側はライン消去の効果音・ボイスのみ再生。SE情報は既存リプレイの検証値に影響させない。
- 「設定」内の「音量」でBGM・SEを個別に0〜100%調整。曲・音量・消音をブラウザーに保存。「コントローラー切り替え」「ボタンの割り当て」も設定内の開閉メニューへ移動。
- [レイアウト画像](レイアウト.png)を参考に、スマホの移動ボタンを丸形にして右へ移動。右回転を右上、左回転を左下に配置し、HOLDを60pxへ拡大。広告は操作ボタンの下に配置する。

## ゲームパッドの根拠と検証範囲

入力配置と取得方法は [W3C Gamepad API](https://www.w3.org/TR/gamepad/#remapping) を参照した。標準配置の右下・右・左・上のボタンをDS4の×・○・□・△として扱う。

ユニットテストでは標準ボタン、同時押し、スティックのヒステリシス、ボタン・軸・生のhat入力の割り当て、切断を検証する。ブラウザーテストでは `navigator.getGamepads()` にDS4相当の入力を供給し、ゲーム画面を操作する。これは実際のUSB・Bluetooth通信やOSのドライバー動作の試験ではない。

## ライン消去演出の実装

型チェック・ユニット／通信テスト83件・ブラウザーテスト18件・ビルドが成功。通常表示と動きを減らす設定、演出終了後のCanvas消去、保存済みリプレイのハッシュ一致を確認。

消える直前の行を描画用コールバックで取得し、盤面の更新や次の操作を待たせずに演出する。描画用データはゲーム状態に保存せず、既存リプレイのハッシュを維持する。オンラインでは最新の消去位置・色・固定番号を追加配信し、先行表示と確定状態の補正で同じ粒を二重発生させない。通信途絶・再接続時に古い消去を再生しないため、45tickより古い演出は省略する。

## 自動進行・遅延改善の検証

2026-09-06、Linux / Chromiumで確認。

- 型チェック・ユニット／通信テスト80件・配信用ビルド成功。

- オンラインとローカル2人対戦は、結果3秒後に自動で次へ進む。切断中は進まず、再接続後に待ち時間を取り直す。
- 先行表示のテストでは、ACK済みの操作を二重実行しないこと、既知のNEXTが尽きた場合や未確定のおじゃまの穴を待つことを検証。
- 実RTCDataChannelの送信に片道150msずつの遅延を加え、参加者のハードドロップ表示は2〜17ms、ホストでの反映は168〜200msだった。補正後の盤面一致と、固定が1回だけであることも確認。人工遅延下での測定であり、実回線の保証値ではない。
- 初期盤面の代表スナップショットはJSON 5,268バイトから1,910バイトへ縮小。同じ状態の通常配信を20Hzから30Hzへ増やしても、ペイロードは約105KB/sから57KB/sへ約45%減る。イベント時の追加送信・プロトコルのオーバーヘッド・入力通信は別。
- ブラウザーテスト16件成功。既存のローカル操作・パッド・リプレイに加え、自動進行、P2P再接続・再戦・人工遅延を確認。
