# 調査根拠と検証計画

[設計書一覧](README.md) / 調査日: 2026-09-06

## 1. 調査の結論と限界

公式マニュアルだけでは、SRS のキック候補、T-Spin の細部、火力表、入力フレーム数、おじゃま到達時間までの完全な実装仕様は得られなかった。公式情報で作品・モード・変更点を固定し、本人による実演・検証と公開研究のモデルを補助根拠にした。

特に **Ver.1.3.2 の REN 調整を反映すること** が重要。更新の存在は公式確認でき、設計の更新後 REN 表はプレイヤーの実演解説を根拠とする。古い表との混同を避ける。[SEGA 更新情報](https://puyo.sega.jp/puyopuyotetris2/information.html)、[更新後の実演記事](https://note.com/blueceru55/n/n053fc510e19b)

今回行ったのは公開資料の調査と設計である。原作ソフトの起動・フレーム計測・改造・内部コードの解析は行っていない。引用先の動画が埋め込まれた記事も、動画の全フレームを独立に検証したものではない。

## 4. 実機照合の進め方

基準機種を1つ固定してから比較する。候補は入力記録を取りやすい Steam 版。機種間で違いが見つかれば共通仕様と差分を分ける。

各検証は `caseId, platform, gameVersion, mode, handicap, settings, initialBoard, piece/next/hold, inputs, observedResult, recordingTimecode, confidence` を記録する。動画ファイルをリポジトリに大量追加せず、タイムコードと必要な再現データを残す。

タイミングは60 fps以上で録画する。画面のフレーム差とゲーム内部tickは同一とは限らないので、入力遅延・録画の重複／欠落を区別し、複数回の中央値と幅を残す。自然落下、消去なし固定、消去あり固定、被弾を別々に測る。

攻撃量は相手が何もしない状態で調べる。相殺された行数と実際にせり上がった行数を混同しない。全消しが混ざると火力表の検証を誤るため、通常火力の試験では盤面に残存ブロックを置く。

## 5. 実装時の受け入れテスト

ここは将来のテスト仕様であり、現時点でテストコードを作成・実行した結果ではない。暫定規則のテストに通っても、原作との一致を確認したことにはならない。

| 対象     | 代表ケース・期待値                                                          |
| -------- | --------------------------------------------------------------------------- |
| SRS      | 左右8遷移×2表。各候補だけが成功する盤面、全候補失敗、I左右非対称を確認      |
| 座標     | 上方向キックが内部盤面で下方向にならない。上端配列外を参照しない            |
| 7-bag    | 大量の列で各袋が7種、同種の連続上限2・不出現上限12。seedで再現              |
| HOLD     | 空／交換でNEXT消費数が異なる。固定前の再使用不可、復帰衝突で敗北            |
| T-Spin   | 2隅は不成立、3隅＋前側条件、4隅、候補5昇格、Mini Double                     |
| 回転履歴 | 失敗入力・0距離HDは維持、位置変更後は解除（初版規約）                       |
| B2B      | Tetris→消去なし→TSDは5。通常Singleを挟むとTSDは4                            |
| REN      | Single3連続の合計1、14連続の合計37。11/12は4、13は5                         |
| 全消し   | 初版は合計10。受信6なら相殺後4。通常Double全消しでB2B解除                   |
| 相殺     | 入力予告 `[2,4]` に攻撃5なら残り `[1]`、余剰なし                            |
| 保留     | 到達済み予告があってもSingle消去では受け入れない                            |
| 上限     | 予告12を消去なし固定で8受け、次の受信機会に4（初版規約）                    |
| 同時処理 | 1P/2Pを交換しても攻撃量・勝敗が対称。乱数ストリームも席と対応させる         |
| 敗北     | 出現衝突、HOLD衝突、全体/部分ロックアウト、消去救済、内部上端overflow       |
| 決定性   | 同一入力・イベント・ルール・初期乱数でブラウザーとサーバーの完全状態が一致  |
| 通信     | 重複seq、遅延、未来tick、旧ラウンド入力を安全に棄却。攻撃イベントの重複なし |
| 切断     | 片側復帰、猶予満了、両側切断、サーバー障害を区別                            |
| 保存     | 結果保存の再送で二重計上なし。リプレイの最終状態と確定結果が一致            |

ルールの変更時は、新しい `rulesVersion` と新しい期待値を追加する。古いリプレイは当時のルール・エンジンで再生できるようにし、既存のルール版の中身を書き換えない。
